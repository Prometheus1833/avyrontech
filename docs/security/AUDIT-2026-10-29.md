# AVYRON security review — 29 October 2026

Scope: `Prometheus1833/avyrontech`, `origin/main` at `87d3fbb`; source review and synthetic local tests. This is an OWASP ASVS and API Security Top 10 guided review, not a certification or a claim that all attack paths have been excluded. No active production testing, remote migration, merge, or deployment was performed.

## Confirmed findings and code treatment

| ID / severity | Evidence and safe reproduction | Impact / likelihood | Treatment in this branch |
| --- | --- | --- | --- |
| S1 high | `projects.ts` generic PATCH accepted `owner_user_id`; local unauthorized-owner regression | A project editor could transfer ownership; medium likelihood | Reject owner mutation; require explicit access for legacy project reads/writes and scoped project creation |
| S2 high | `projects.ts` link upsert conflicted on global ID without project condition; synthetic cross-project ID test | Write into another project; medium likelihood | Conflict update constrained by project ID and checked for zero changes |
| S3 high | `leads.ts` allowed staff access to unassigned legacy leads; synthetic staff test | Read or edit another lead; medium likelihood | Remove fallback; require assignment, organization access or explicit capability |
| S4 high | `projects.ts` staff sales query returned all paid revenues; scoped synthetic test | Cross-client financial disclosure; medium likelihood | Filter by client access, project staff or active privileged organization membership |
| S5 medium | `index.ts` accepted arbitrary `*.avyrontech.pages.dev` origins; origin policy test | Cross-origin requests from an unrelated Pages site; medium likelihood | Require exact configured origins |
| S6 medium | Several JSON/form parsers ran before a byte bound; forged `Content-Length` stream test | Memory or CPU abuse; medium likelihood | Global API limit before parsing, counted on actual bytes; explicit larger limits for legitimate upload routes |
| S7 medium | `enginePolicy.ts` URL checks differed from metadata fetch policy; private IP cases tested | SSRF policy drift; medium likelihood | Reuse one metadata URL validator and HTTPS only for engine sources |
| S8 medium | `media.ts` accepted SVG and trusted declared MIME; synthetic signature tests | Active content or mislabeled file in R2; medium likelihood | Reject SVG, enforce extension/signature and attachment disposition for non-image media |
| S9 medium | Project/resource URLs could reach browser anchors without historical-value validation; executable scheme tests | Script/navigation abuse if malicious value existed; medium likelihood | Validate on write and on render |

Tests cover both rejected attacks and ordinary authorized operations. The upload checks establish format consistency only: they are not malware scanning or archive inspection.

Local microbenchmark of a 1 KiB POST through the Hono route (300 measured iterations, 30 warmups) measured baseline p50/p95 0.099/0.208 ms and body-limit p50/p95 0.176/0.389 ms. This is a local handler comparison, not production latency or memory evidence; monitor upload memory and p95 after an approved deployment.

## Operations preparation

- **WAF / rate limits:** inventory current rules and plan entitlements first. Stage a monitor/log rule for unusual auth, upload and webhook traffic; use per-route thresholds based on seven days of baseline, exempt verified provider webhook delivery and accessibility tooling, then approve enforcement. Rollback is disabling the specific new rule; monitor legitimate 4xx/429 rates and checkout completion.
- **Detection:** route sanitized security events and Worker exceptions to an alert destination with owner and escalation; alert on auth brute force, unexpected 403/429 spikes, webhook failures, AI spend and D1/R2 restore failures. Keep payloads, tokens and PII out of logs.
- **Recovery:** document secret owners and rotation order, maintain a break-glass path, rehearse session revocation, use D1 Time Travel and R2 restore in an isolated environment, and record target recovery time/data loss before enabling automated backup jobs.
- **Retest cadence:** rerun dependency and code scanning on every PR; recheck GitHub/Cloudflare effective settings after an authorized change and after provider or binding changes.
